# Gráficos del panel vía GraphQL — guía para el frontend

Contrato de `POST /api/metrics`. Fuente de verdad: `app/GraphQL/MetricsGraphQL.php` (esquema) y `app/Services/MetricsService.php` (datos). Si cambia alguno, actualizar este archivo y `TASKS/front-end.md` (C1).

## 1. Transporte

| | |
|---|---|
| Endpoint | `POST /api/metrics` |
| Auth | `Authorization: Bearer <token>` (Sanctum) |
| Roles | `DIR-01`, `AD-01`. Otros roles → 403 |
| Body | `{ "query": "...", "variables": {...}, "operationName": "..." }` |
| Límites | profundidad 6, complejidad 200, 120 solicitudes/min por usuario |
| Introspección | solo fuera de producción |

**Errores.** Los de consulta o datos llegan con **HTTP 200** y `errors[0].message` en español (`groupBy "x" no es válido para LOANS. Opciones: ...`). Solo 401 (sin token / token inválido) y 403 (rol) usan código HTTP. Siempre revisar `errors` antes de leer `data`.

**No usar datos de respaldo cuando falla.** Mostrar el `message` del error; un *fallback* a cifras fijas oculta errores reales.

## 2. Esquema

```graphql
enum MetricEntity { EQUIPMENT SUPPLIES LOANS ALERTS MAINTENANCE CAREERS TEACHERS }
enum MetricAggregation { TOTAL AVERAGE COUNT RATE }
enum TimeRange { LAST_7_DAYS LAST_30_DAYS SEMESTER_CURRENT SEMESTER_PREVIOUS YEAR_TO_DATE CUSTOM }
enum ChartType { BAR LINE DOUGHNUT POLAR_AREA }

input MetricQueryInput {
  entity: MetricEntity!
  metric: MetricAggregation!
  timeRange: TimeRange!
  chartType: ChartType!        # solo se devuelve tal cual; el backend no cambia datos por él
  title: String                # ignorado
  groupBy: String              # ver §4
  dateFrom: String             # YYYY-MM-DD, obligatorio con CUSTOM
  dateTo: String               # YYYY-MM-DD, opcional (por defecto hoy)
  limit: Int                   # 1-50, por defecto 10; solo recorta rankings
}

type MetricDataPoint { label: String!  value: Float!  secondaryValue: Float  category: String }
type MetricResult {
  entity: MetricEntity!  metric: MetricAggregation!  timeRange: TimeRange!  chartType: ChartType!
  points: [MetricDataPoint!]!
  summary: String
}
type ExecutiveKpis {
  activosDisponibles: Int!  activosEnPrestamo: Int!  activosEnTaller: Int!  activosDeBaja: Int!
  prestamosActivosHoy: Int!  tasaAtrasosPct: Float!
  alertasCriticasNoResueltas: Int!  tasaRotacionMensualPct: Float!
}
type Query {
  executiveKpis(timeRange: TimeRange): ExecutiveKpis!      # por defecto LAST_30_DAYS; CUSTOM → error
  customMetric(input: MetricQueryInput!): MetricResult!
}
```

## 3. Consultas

Tarjetas (KPIs):

```graphql
query GetExecutiveKpis($timeRange: TimeRange) {
  executiveKpis(timeRange: $timeRange) {
    activosDisponibles activosEnPrestamo activosEnTaller activosDeBaja
    prestamosActivosHoy tasaAtrasosPct alertasCriticasNoResueltas tasaRotacionMensualPct
  }
}
```

`tasaRotacionMensualPct` se calcula sobre el `timeRange` pedido (no solo el mes). `tasaAtrasosPct` y `tasaRotacionMensualPct` ya vienen en porcentaje (0-100).

Cualquier gráfico:

```graphql
query GetCustomMetric($input: MetricQueryInput!) {
  customMetric(input: $input) {
    entity metric timeRange chartType summary
    points { label value secondaryValue category }
  }
}
```

Ejemplo de variables y curl:

```json
{ "input": { "entity": "LOANS", "metric": "COUNT", "timeRange": "LAST_30_DAYS", "chartType": "BAR", "groupBy": "status" } }
```

```sh
curl -s localhost:8000/api/metrics \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"query":"query($input:MetricQueryInput!){customMetric(input:$input){points{label value}}}","variables":{"input":{"entity":"LOANS","metric":"COUNT","timeRange":"LAST_30_DAYS","chartType":"BAR"}}}'
```

Respuesta típica:

```json
{ "data": { "customMetric": {
  "points": [ { "label": "Semana 1", "value": 12.0, "secondaryValue": null, "category": null } ],
  "summary": "Préstamos · COUNT · 2026-10-01 a 2026-10-30 · 5 punto(s)" } } }
```

## 4. Qué devuelve cada entidad

El período filtra por fecha del préstamo, de la alerta o del informe. `EQUIPMENT` es una foto del inventario actual (el período no lo afecta). `EQUIPMENT` solo incluye productos con `type: equipo` y `SUPPLIES` solo `type: insumo`.

| Entidad | Sin `groupBy` | `groupBy` válidos |
|---|---|---|
| `LOANS` | **serie en el tiempo**: `Semana N` si el rango ≤ 31 días, `YYYY-MM` si es más largo | `status`, `teacher`, `subject`, `item_type` |
| `SUPPLIES` | ranking de productos por consumo; `secondaryValue` = stock restante | `career`, `category`, `turnover` (alta / media / baja / sin movimiento) |
| `EQUIPMENT` | ranking de más solicitados; `secondaryValue` = stock | `hardware_category` (alias `category`), `location`, `physical_condition` (disponible / en taller / dado de baja) |
| `ALERTS` | serie en el tiempo | `criticality` (Crítica / Advertencia), `specialty_area` |
| `MAINTENANCE` | serie en el tiempo | `equipment`, `failure_type` (Leve / Media / Crítica; es la gravedad), `workshop` |
| `CAREERS` | préstamos por carrera | `specialty`, `level` (Técnico de Nivel Superior / Profesional / Sin nivel) |
| `TEACHERS` | ranking de docentes | `subject`, `department` |

Un `groupBy` fuera de la tabla devuelve error. `CAREERS.level` sale del catálogo `/api/careers`, unido por nombre con el `area` del solicitante.

## 5. Semántica de `metric`

| Métrica | `value` |
|---|---|
| `COUNT` | número de registros del grupo |
| `TOTAL` | unidades prestadas (suma de cantidades) |
| `AVERAGE` | unidades por registro |
| `RATE` | % del grupo sobre el total (los puntos suman 100) |

- En `ALERTS` y `MAINTENANCE` no hay unidades: `TOTAL` y `AVERAGE` devuelven el conteo y `summary` lo avisa. Se puede ocultar esas opciones en el constructor para esas entidades.
- `LOANS` + `RATE` + sin `groupBy` es un caso especial: devuelve la dona de puntualidad con tres puntos (*Devuelto a tiempo*, *Activo*, *Atrasado*).
- `value` viene redondeado a 1 decimal.

## 6. Cómo pintar los puntos

- **Series en el tiempo** (`LOANS`, `ALERTS`, `MAINTENANCE` sin `groupBy`): `label` = eje X, `value` = eje Y. Ya vienen en orden cronológico; no se recortan con `limit`. Ideal para `LINE` o `BAR`.
- **Rankings y agrupaciones**: vienen ordenados de mayor a menor `value` y recortados a `limit`. Ideal para `BAR`, `DOUGHNUT` o `POLAR_AREA`.
- `secondaryValue` (opcional): segunda medida del mismo punto. En `SUPPLIES` y `EQUIPMENT` sin `groupBy` es el stock restante; sirve para el gráfico de proyección de agotamiento o una segunda barra/tooltip. Puede ser `null`.
- `category` (opcional): agrupación extra del punto, puede ser `null`. Usarla para color o leyenda si viene.
- `points` puede venir **vacío**: mostrar estado "sin datos para el período", no un gráfico roto.
- `chartType` es una preferencia del cliente: cualquier combinación es válida a nivel de API. Dona y área polar solo tienen sentido con pocas categorías (usar `limit` ≤ 8) y con `RATE` o `COUNT`.
- `summary` es texto listo para un pie de gráfico o tooltip (incluye rango de fechas y avisos).

## 7. Períodos

`LAST_7_DAYS`, `LAST_30_DAYS`, `SEMESTER_CURRENT`, `SEMESTER_PREVIOUS`, `YEAR_TO_DATE`: el backend resuelve las fechas. `CUSTOM` exige `dateFrom` (`YYYY-MM-DD`) y acepta `dateTo`. Errores posibles: `CUSTOM requiere dateFrom ...`, `dateFrom / dateTo deben tener formato YYYY-MM-DD.`. Las fechas son de calendario en UTC; el rango efectivo aparece en `summary`.

## 8. Limitaciones conocidas

- `executiveKpis` suma todos los productos, sin separar equipo de insumo.
- `title` se ignora; el título del gráfico lo pone el frontend.
- Los endpoints REST `GET /api/dashboard/*` siguen vivos pero son legado; los gráficos nuevos deben usar GraphQL.
